Answer the right template, then recover

Every answers file identifies its template before Toha can evaluate an answer or change staged work.

Task

Require template identity in every answers file, then decide how incomplete staged interviews recover.

Pre-mortem — the build failed. Why?

  • The wrong template accepted the file. Question ids matched before identity was checked.
  • A crate caller bypassed the check. A public parser returned raw answers.
  • Continue consumed too much. One broad helper replaced its one-step behavior with an apply walk.
  • A mismatch changed state. Staged answers, flow, planning, files, or hooks ran before the check.
  • Identity became a resolver. File data triggered alias lookup, path normalization, fetch, or trust.
  • The correction grew into another restriction. Files became bound to a target, commit, or version.

Protocol owns the file boundary. The interview engine remains pure. Staging, planning, and target ownership stay where they are.

One identity authority

  • The source resolver produces the formal template name.
  • The staged record stores that same formal name.
  • Question output already publishes it as context.template.
  • The answers file copies that exact string.
  • The consumer compares strings. It does not resolve the declaration.

Validation order

  1. Establish target, staged record, source, template, configured values, and replay.
  2. Refuse wrong command identity or unused input before opening the file.
  3. Read once; validate JSON and the two-field envelope.
  4. Recognize a legacy bare map and show wrapper guidance.
  5. Compare the declared template with the established formal name.
  6. Only then parse question ids and enter the interview engine.
  7. Only an accepted result can reach staged, flow, plan, target, or hook effects.

A malformed envelope wins over mismatch. Mismatch wins over every answer fault.

Identity failure is atomic

A missing, malformed, or mismatched identity produces no:

  • answer evaluation or accepted submission;
  • answer-derived warning, message, or flow result;
  • staged save, removal, or migration;
  • plan, target write, hook, or trust evaluation.

Existing configured-value warnings keep their route-preparation timing. Existing source resolution can populate its cache before file read.

Out of scope

  • Binding answer files to a target or commit.
  • Resolving or normalizing identity declared by a file.
  • Adding identity to staged submissions or in-memory RawAnswers.
  • Changing configured-default provenance or canonical target construction.
  • Changing trust, permissions, access, timeouts, dependency-version policy, or subprocess use.
  • Implementing runtime or shared specification changes in this design task.

Dependencies: current epic basis and error producer.

Reviewer focus — what to attack

  • Submit another template's file. Use identical question ids and valid values.
  • Bypass the gate from the crate. Try to obtain raw answers from external JSON.
  • Make continue walk two batches. It must remain one answer step.
  • Cause an effect before identity succeeds. Watch store, plan, target, hook, and trust calls.
  • Trigger a second resolver. The document declaration must remain inert data.
  • Add target, commit, or version coupling. Same-template reuse must still pass.

Decisions needed first

1 — Target-only answers

1A — Resume and apply (recommended).

apply PATH --answers FILE uses the staged record, checks the file identity, saves accepted progress, and applies on completion.

1B — Keep the refusal.

Require continue or a repeated template operand.

1A uses the target identity that already exists and adds the independent file assertion.

2 — Exit-4 output on a terminal

2A — Show a concise summary (recommended).

Apply and continue show remaining questions and the next command. Pipes, redirects, and stage --async stay JSON.

2B — Always show JSON.

Keep one representation for terminal and non-terminal stdout.

2A changes terminal stdout only. Exit 4 and machine JSON stay stable.

3 — Named recovery

3A — Preserve matching recovery (recommended).

apply TEMPLATE PATH --answers FILE resumes when command, staged, and document identities agree.

3B — Refuse named recovery.

Require target-only recovery or continue whenever state exists.

3A preserves the supported assertion route and the staged immutable source.

Complexity with this plan

Moderate.

  • Two operations preserve real one-step and headless engine behavior.
  • One staged-effect policy keeps flow and persistence consistent.
  • Existing source identity, target identity, configured origins, interview logic, and planning remain authoritative.
