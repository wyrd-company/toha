Pre-mortem — where this could fail

  • Hidden reference: debug(), an alias, or an included body bypasses admission.
  • State advances: stage asks a question before refusing missing trust.
  • Replay drifts: a later batch reads the current host or registry again.
  • Target splits: context reconstructs producer-owned identity.
  • Compatibility narrows: a folder edit starts requiring restage.

Pre-mortem — protections in the design

  • Compile and analyze every supported Jinja surface at template load.
  • Refuse before capture, seed, interview, render, submission, or store write.
  • Persist a closed snapshot; replay performs no ambient access.
  • Accept only the producer-created CanonicalTarget.
  • Keep current mutable-folder behavior; do not add a source-identity gate.

Direct and apply keep approved trust

  • Explicit --trust grants the fixed environment values.
  • An eligible named user/system entry can use a current matching reviewed approval.
  • Folder, direct Git, bundled, and local-layer selections still need the flag.
  • Stage is different: any need requires its explicit flag; a supplied flag is carried even without a need.
  • Staged apply --trust controls hooks only; it cannot elevate the recorded Jinja snapshot.

Behaviors to prove — admission and replay

  • Missing stage trust: named error and zero reads, questions, renders, submissions, or writes.
  • No refs, no flag: unavailable and zero reads.
  • No refs, explicit stage flag: all five captured exactly once.
  • Refs, no flag: refusal before interview or state progress.
  • Refs, flag: all five captured exactly once.
  • Continue: no trust option and no host, registry, privilege, terminal, or environment read.
  • Staged apply trust: hook permission changes; Jinja snapshot does not.
  • Legacy record: old availability, collisions, and debug() output remain.

  • Only the 17 exact names collide; neighboring toha_ names remain legal.
  • Configured Resolution keeps winning file/layer origin; ordinary Seed.defaults stays flat.

Alternatives rejected

  • Exact-name undeclared-variable scan alone: misses debug(), self-shadowing, and includes.
  • Referenced-values-only storage: needs a source gate or produces false nulls.
  • Persisted render program: silently ignores later folder edits.
  • Stored grant with later reads: replay depends on ambient state.
  • Trust on continue: reintroduces abort/retry behavior.
  • Unsupported-syntax refusal: narrows currently supported templates.

Approved — stage trust happens once

APPROVED

  • Find all possible environment references before the interview.
  • Require explicit stage --trust when any need exists.
  • When supplied, capture all five once even if no initial need exists.
  • Fail before interview and staged-state progress when the flag is missing.
  • Carry the decision through later batches.
  • No continue --trust, later access check, or access abort/retry.

Approved — bounded plaintext snapshot

APPROVED

Store up to five optional plaintext values in the existing staged JSON after a carried stage grant or admitted direct/apply need.

  • At most four may be extra when one fixed name is referenced.
  • debug() requires all five.
  • No flag and no need means no environment values are stored.
  • Existing state-directory and process-umask behavior applies.
  • Values remain until apply, abort, or operator removal.

Approved — mutable-folder replay

APPROVED

Current folder bytes render under the recorded decision.

  • Unavailable stays unavailable; later references receive null.
  • Captured makes the recorded fixed-five snapshot available.
  • No later host read, access request, or registry check occurs.
  • No new source-change refusal is introduced.

Complexity — bounded by the plan

  • No runtime version check; dependency changes fail at compile time.

  • Literal Jinja includes use the already integrated include contract.
