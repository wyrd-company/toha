Pre-mortem — what could still fail?

  • Interview and files disagree: a caller rebuilds context.
  • Resume changes an earlier branch: replay reads the host again.
  • Revoked trust still exposes values: replay skips the live gate.
  • Template data is shadowed: a reserved name reaches runtime.
  • Presets become Jinja globals: two namespaces are mixed.
  • Target identity drifts: a consumer normalizes or reconstructs it.

Out of scope

  • Runtime, specification, schema, or guide edits in this design task
  • Approval or modification of the canonical-target carrier decision
  • Arbitrary environment access or dynamic lookup
  • Trust commands or review-digest changes
  • A second target normalizer or unchecked target constructor
  • Configured-preset behavior or naming changes
  • New timeouts, pinned checks, permissions policy, or subprocess integration

Reviewer focus

  • Context split: can interview and plan observe different facts?
  • Target drift: does any consumer normalize or construct identity?
  • Trust bypass: can replay use stored values after access is lost?
  • Environment expansion: can any sixth process value cross?
  • Collision hole: can authored data shadow a reserved name?
  • Preset overlap: can config presets appear as Jinja context?
  • Leakage: can a granted value enter debug, errors, or protocol output?

Alternatives rejected

  • MiniJinja globals: hidden process state
  • Plan-only context: interview remains incomplete
  • Re-read on resume: earlier branches can change
  • Stored grant without live access: revocation has no effect
  • Separate environment permission: outside the requested trust gate
  • Consumer target wrapper: duplicates producer ownership
  • Reserve all toha_ names: unsupported restriction

Decision 1A — effective template trust

--trust or a current matching reviewed-registry approval grants the five values.

RECOMMENDED

  • One content-bound trust decision for the invocation
  • Folder, direct Git, local-registry, and bundled templates still require --trust

Decision 1B — command flag only

Only --trust grants the five values.

NARROWER

  • Registry approval remains hook-only
  • Reviewed templates require another explicit action for these values

Decision 2 — staged access and storage

  • Add existing --trust spelling to stage and continue
  • Capture only user, hostname, editor, shell, and visual after access
  • Store at most those five normalized values as plaintext in existing staged state
  • Require current access before replay of a granted snapshot

EXPLICIT PERMISSIONS / ACCESS APPROVAL REQUIRED

Decision 2 — replay examples

One-run grant

toha stage --trust sample ./output --async
toha continue --trust ./output answers.json

Repeat --trust before replay.

Saved denial

toha stage sample ./output --async
toha continue --trust ./output answers.json

The saved denial stays denied. Start a new interview to change it.
