Toha 0.2.0 · Design brief · Phase C

Errors point to their owner

Preserve template and config provenance, keep answer documents atomic, and give every target consumer one canonical identity.

Approved design design only implementation contract ready

Task

Make six related failures actionable without splitting behavior by caller.

  • File-rule and rendered-path faults name the exact template field.
  • A bad template default is a template fault.
  • A bad configured default names its winning config entries and stays recoverable.
  • Early answers produce only relevant errors.
  • Existing and future target directories have one separator-free identity.

Terminal, headless, staged, direct, replay, and crate callers use the same engine paths.

Pre-mortem — the implementation failed

  • Attribution was rebuilt from an id. The winning config file was lost.
  • A probe changed state. A rejected document emitted a warning or hook.
  • A rejected answer proved a skip. The engine hid a real early error.
  • Terminal gained special policy. Headless and replay behavior drifted.
  • A raw path bypassed normalization. Store and Jinja identities differed.
  • Old staged work disappeared. The corrected target hashed to a new key.

Public interfaces expected

Configured defaults: preserve ordinary Seed

pub struct Seed {
    pub now: Zoned,
    pub defaults: IndexMap<Id, RawAnswer>,
}

impl Resolution {
    pub fn warnings(&self) -> &[String];
    pub fn start(self, template: &Template, now: Zoned)
        -> Result<Interview, EvalError>;
    pub fn into_flat_defaults(self)
        -> (IndexMap<Id, RawAnswer>, Vec<String>);
}

Ordinary crate defaults keep the flat seed. Configured callers consume one value-plus-origin result.

Replay: same configured capability

impl StagedRecord {
    pub fn replay_with_resolution(
        &self,
        template: &Template,
        resolution: Resolution,
    ) -> Result<Interview, StagingError>;
}

// Existing replay and replay_with_defaults remain.

Resume re-reads live config; no origin or derived state is serialized.

Target: one enforceable constructor

pub struct CanonicalTarget(PathBuf);

pub fn canonical_target(path: &Path)
    -> Result<CanonicalTarget, StagingError>;

impl CanonicalTarget {
    pub fn as_path(&self) -> &Path;
}

Store, record, protocol, plan, apply, and Jinja context accept &CanonicalTarget. There is no unchecked conversion.

Data structures expected

Configured value and exact origin stay together

struct ResolvedDefault {
    raw: RawAnswer,
    origin: ConfiguredDefaultOrigin,
}

struct ConfiguredDefaultOrigin {
    mapping: MappingSite,
    preset: Option<PresetSite>,
}

Both sites derive once from the winning config entries. The interview engine does not know layers, selectors, or preset lookup.

One answer document, one transaction

struct SubmissionTxn {
    original: Pending,
    valid_current: Answers,
    rejections: Vec<PendingRejection>,
    early_failures: IndexMap<Id, usize>,
}

enum SkipDisposition { Active, Skipped, Unresolved }

A rejected transaction returns the original state. The probe publishes no effects.

One template-fault text contract

pub(crate) struct TemplateFault {
    field: String,
    expression: Option<String>,
    message: String,
}

Interview and planning keep their own error context. This private value owns only the shared field, expression, and message format.

Routes and target identity

  • Direct apply, continue, staged apply, replay, terminal, and crate results match.
  • Existing and future directories have one separator-free spelling.
  • An old separator-keyed record loads and moves only after a successful save.
  • Compile-fail checks reject a raw path at every target consumer.

Out of scope

  • Configured-default naming, selection, precedence, migration, and config schema.
  • New protocol fields or statuses.
  • Trust, permissions, access, hooks, timeouts, or pinned-version checks.
  • Application subprocess integration.
  • A second target normalizer in Jinja context.
  • A general error-code or localization redesign.

Reviewer focus

  • Try to separate a configured value from its winning origins.
  • Make a rejected current answer prove a later skip.
  • Find any probe effect that escapes a rejected document.
  • Pass a raw path into storage, protocol, planning, apply, or Jinja context.
  • Lose a warning on one configured-resolution caller.
  • Break an old staged record during the target-key correction.

Alternatives explored

Alternative Why it lost
Replace flat Seed defaults Breaks ordinary crate defaults and leaks config provenance.
Parallel value and origin maps They can drift and make every caller coordinate invariants.
Terminal-only default check Splits policy and does not match the current terminal flow.
Separate skip oracle Duplicates traversal and dependency semantics.
Keep raw PathBuf Crate callers can bypass the normalization authority.

Approved decisions

1 · Early failure when skip is unresolved

A · Reject now — approved

The value already fails an answer-independent rule, so accepted staged history stays valid.

B · Defer — rejected

Accept the document and report the known failure only when the question is reached.

2 · Proven skipped beside another failure

A · Omit it — approved

The value is unused. Keep the real current error; emit no warning until a corrected document commits.

B · Keep it — rejected

Return an error for the unused early value whenever any current answer fails.

3 · Skipped template default

A · Check ready rules — approved

A template-owned value must satisfy every rule already knowable; unavailable dynamic rules do not block the skipped branch.

B · Active questions only — rejected

A skipped default can violate its ready template rules and still enter downstream answers.

4 · Configured provenance seam

A · Consuming Resolution — approved

Keep flat Seed for ordinary callers; configured start and replay consume one value-plus-origin result.

B · Companion maps — rejected

Keep the current resolver result and ask callers to synchronize values with origins.

A amends the configured-default interface before its implementation. It does not change its approved user behavior.

5 · Canonical target carrier

A · Opaque type — approved

Only the canonical constructor can create target identity; compile-time checks cover every consumer.

B · Keep PathBuf — rejected

Fewer signature edits, but public crate callers can bypass normalization.

Capability approved A removes raw &Path access from supported public target-consuming methods.

Size

Expected agent implementation time: one to two focused days.

  • Configured start/replay seam and prompt preparation.
  • One answer transaction and route-equivalence matrix.
  • Canonical target type and legacy state-key compatibility.
  • Canonical specification and guide updates.

Complexity

Moderate with this plan.

  • No new dependency, concurrency, service, or protocol shape.
  • One state-machine policy path for every caller.
  • Compile-time target enforcement increases signature edits but reduces runtime ambiguity.
  • The largest risk is proving effect-free reachability beside a failed current answer.

The paired implementation is bound to this design after independent review and integration.
